Why Use Databases?

Databases store billions of records on storage devices like SSDs, hard drives, and disks. PostgreSQL, MongoDB, and MySQL are similar to Excel spreadsheets, but much more powerful.

Why not use Excel?
- Excel works well for small datasets (less than 100,000 rows)
- Excel becomes slow and crashes with larger data (millions or billions of rows)

Why use Databases?
- Handle massive amounts of data efficiently
- Retrieve data much faster than Excel
- Organize and arrange data in structured ways
- Support multiple users accessing data simultaneously
- Provide better security and data protection

So if a database contains 3 billion rows, they are stored as files on disk, similar to how Excel files exist on disk.

EG structure of Database servers:

database_server
   ├── users_table.data
   ├── orders_table.data
   ├── indexes
   └── transaction_logs


DBs use RAM(memory) used as a cache

SELECT Statement:

- The SELECT statement is used to retrieve data from a database table.
- Syntax:
       SELECT column1, column2 FROM tablename;
       SELECT * FROM tablename;  -- Selects all columns (not recommended for production)

Note: Avoid using SELECT * in production queries as it can slow down performance and return unnecessary data.

WHERE Clause:

- The WHERE clause filters rows based on specified conditions.
- Syntax:
       SELECT column1 FROM tablename WHERE condition;

- You can combine multiple conditions using AND, OR, and NOT.
- Always use correct data types and be careful with NULL values (use IS NULL or IS NOT NULL).

Example:
SELECT * FROM film WHERE rental_rate > 4 AND replacement_cost >= 19.99;

ORDER BY Clause:

- ORDER BY sorts the result set by one or more columns.
- Default order is ASC (ascending). Use DESC for descending order.
- Syntax:
       SELECT column1 FROM tablename ORDER BY column1 ASC, column2 DESC;

- For text columns, sorting is alphabetical; for numbers, it’s numeric.

LIMIT Clause:

- LIMIT restricts the number of rows returned.
- Syntax:
       SELECT * FROM tablename LIMIT number_of_rows;

- Useful for previewing data or paginating results.

BETWEEN & NOT BETWEEN:

- BETWEEN checks if a value is within a range (inclusive).
- NOT BETWEEN checks if a value is outside a range.
- Works with numbers, dates (in YYYY-MM-DD format), and text.

Example:
SELECT COUNT(*) FROM payment WHERE amount NOT BETWEEN 8 AND 9;

Points to Remember:
- BETWEEN is inclusive (includes boundary values).
- For dates, ensure the format matches the database standard.
- Use WHERE with caution to avoid unintentional data filtering.

Primary and Foreign key:

Primary key: a column that uniquely identifies each row in a table. It should be unique, not null.

Foreign key: It ia a column of data in one table that points to the primary key of the other table. connects one table to another table.  Can have duplicates but must match the value in referenced primary key. Can be "Null"

What are constraints?
Constraints are set of rules applied in a column of a database table to prevent invalid data into the database. This ensures the accuracy and reliability of the data in the database.

Types:
Constraints on column
Constraints on table


Common COLUMN Constraints:
1. NOT NULL constraint. (All values of the table in a column of a table should not contain Null value)
2. UNIQUE Constraint. (Uniquely identifies the data in a column of a table)
3. PRIMARY KEY Constraint (Uniquely identifies each row / record of a table)
4. FOREIGN KEY Constraint. (Constraints data based on columns in other tables)
5. CHECK Constraint. (Ensures certain checks or conditions are satisfied)
6. EXCLUSION Constraint. 


Common TABLE Constraints:
1. CHECK Constraint.
2. REFERENCE Constraint.
3. UNIQUE Constraint.
4. PRIMARY KEY Constraint
