SQL Notes

General Guidelines:
-------------------
- SQL syntax is generally applicable to all relational databases (e.g., PostgreSQL, MySQL, etc.).
- Avoid using SELECT * unless you need all columns. Selecting all columns can slow down your application and increase network traffic.
- Capitalize all SQL keywords for readability. End each statement with a semicolon (;).
- Use lowercase for table and column names to distinguish them from SQL keywords.
- Avoid using SQL reserved keywords as table or column names. If unavoidable, use double quotes (e.g., "length") but it's better to choose different names.
- Notice that SQL language is case insensitive.

SELECT:
------
- The SELECT statement is used to retrieve data from one or more tables.
- You can specify which columns to retrieve, or use * to select all columns (not recommended for production).
- Syntax: SELECT column1, column2 FROM table_name;
- Always end statements with a semicolon (;).

Example:
SELECT first_name, last_name FROM customer;

Scenario:
Retrieve all customer emails from the customer table.
Solution:
SELECT email FROM customer;

DISTINCT:
---------
- DISTINCT is used to remove duplicate values from the result set.
- It applies to all columns listed after SELECT DISTINCT.
- Useful when you want to see only unique values.

Example:
SELECT DISTINCT city FROM address;

Scenario:
Find all unique ratings from the film table.
Solution:
SELECT DISTINCT rating FROM film;

DISTINCT ON:
------------
- DISTINCT ON is a PostgreSQL-specific feature.
- It returns the first row of each set of rows where the given expressions are equal.
- You must use ORDER BY to control which row is returned for each group. Note that the first column you use with ORDER BY should match with the column you use with DISTINCT ON.
- Note the column we use with DISTINCT ON inside the () will also be used with SELECT clause. 

Syntax:
SELECT DISTINCT ON (column) column, other_columns
FROM table
ORDER BY column, other_columns;

Example:
SELECT DISTINCT ON (customer_id) customer_id, payment_date, amount
FROM payment
ORDER BY customer_id, payment_date DESC;

Scenario:
For each customer, get their most recent payment.
Solution:
SELECT DISTINCT ON (customer_id) customer_id, payment_date, amount
FROM payment
ORDER BY customer_id, payment_date DESC;


WHERE:
------
- The WHERE clause is used to filter records that meet specific conditions.
- It comes after the FROM clause and before GROUP BY, HAVING, or ORDER BY.
- WHERE can use comparison operators (=, <, >, <=, >=, <>, !=), logical operators (AND, OR, NOT), and pattern matching (LIKE, IN, BETWEEN).
- WHERE only filters rows before aggregation; to filter after aggregation, use HAVING.

Syntax:
SELECT column1, column2
FROM table_name
WHERE condition;

Examples:
- Select all customers from city_id 300:
  SELECT * FROM customer WHERE city_id = 300;

- Select all films with a rating of 'PG':
  SELECT title FROM film WHERE rating = 'PG';

- Select all payments greater than $5:
  SELECT * FROM payment WHERE amount > 5;

- Select customers with first name 'John' and last name 'Smith':
  SELECT * FROM customer WHERE first_name = 'John' AND last_name = 'Smith';

- Select films released between 2005 and 2010:
  SELECT title FROM film WHERE release_year BETWEEN 2005 AND 2010;

- Select customers whose email ends with 'gmail.com':
  SELECT * FROM customer WHERE email LIKE '%gmail.com';

Edge Cases & Notes:
-------------------
- NULL values: Comparisons with NULL using = or <> will not return true. Use IS NULL or IS NOT NULL.
  Example: SELECT * FROM customer WHERE email IS NULL;

- Case sensitivity: String comparisons are case-insensitive in most databases, but not all. Use ILIKE in PostgreSQL for case-insensitive matching.

- Multiple conditions: Use parentheses to control logical operator precedence.
  Example: SELECT * FROM film WHERE (rating = 'PG' OR rating = 'G') AND length > 120;

- No matching rows: If no rows match the WHERE condition, the result set is empty.

- WHERE with JOIN: You can use WHERE to filter results after joining tables.
  Example: SELECT * FROM payment JOIN customer ON payment.customer_id = customer.customer_id WHERE payment.amount > 10;

Scenario:
---------
Find all customers who have made a payment greater than $50.

Solution:
SELECT customer_id, amount
FROM payment
WHERE amount > 50;

Scenario:
---------
Find all films with a title starting with 'A' and a length less than 90 minutes.

Solution:
SELECT title, length
FROM film
WHERE title LIKE 'A%' AND length < 90;

Scenario:
---------
Find all customers who do not have an email address.

Solution:
SELECT customer_id, first_name, last_name
FROM customer
WHERE email IS NULL;

Summary:
--------
- Use WHERE to filter rows before aggregation or grouping.
- Always use IS NULL/IS NOT NULL for NULL checks.
- Combine conditions with AND/OR and use parentheses for clarity.
- WHERE is essential for precise data retrieval and query optimization.


COUNT():
--------
- Use COUNT() to return the number of rows matching a query.
- Example: SELECT COUNT(*) FROM table_name;

String Literals:
----------------
- Use single quotes for string values in SQL.
- Example: WHERE rating = 'R'

ORDER BY:
---------
- Use ORDER BY to sort results by one or more columns.
- You can specify ASC (ascending, default) or DESC (descending).
- You do not have to select the column you sort by, but including it improves clarity.
- Example: SELECT title FROM film ORDER BY length DESC;

LIMIT:
------
- Restricts the number of rows returned.
- Syntax: SELECT * FROM table LIMIT n;
- IF n is NULL. It returns all the rows. If n is 0 then no rows will be returned. If n is a negative number (EG: -2) then it will through error like limit cannot be negative.
- If we want to skip the rows then use OFFSET with LIMIT. 

Syntax: LIMIT 5 OFFSET 3   -> It will omit the first 3 (1, 2, 3) rows then it will return 5 rows starung from 4 (4, 5, 6, 7, 8). 

Scenario:
Get the first 5 customers.
Solution:
SELECT * FROM customer LIMIT 5;

BETWEEN & NOT BETWEEN:
----------------------
- Use BETWEEN to filter results within a range (inclusive).
- For dates, use ISO 8601 format (YYYY-MM-DD).
- Example: WHERE date BETWEEN '2023-01-01' AND '2023-12-31'
- Be cautious with date ranges; check database documentation for inclusivity.

IN & NOT IN:
------------
- Use IN to match any value in a list.
- Example: WHERE color IN ('red', 'blue', 'green')
- Use NOT IN to exclude values.
- Example: WHERE color NOT IN ('red', 'blue', 'green')
- Sub Query : use IN and NOT IN with Sub Query


LIKE & ILIKE:
-------------
- LIKE is used for pattern matching (case-sensitive).
- ILIKE is used for case-insensitive pattern matching (PostgreSQL only).
- % matches any sequence of characters.
- _ matches a single character.
- Examples:
  - WHERE name LIKE 'A%'      -- names starting with 'A'
  - WHERE name LIKE '%a'      -- names ending with 'a'
  - WHERE last_name LIKE '%eh%'   -- contains 'eh'
  - WHERE last_name LIKE '_eh%'   -- second and third letters are 'eh'
  - WHERE first_name NOT LIKE '%her%' -- does not contain 'her'
- Combine % and _ for flexible patterns.
- Note: LIKE is case-sensitive in most databases; use ILIKE for case-insensitive search in PostgreSQL.

Best Practices:
---------------
- Always use clear and descriptive names for tables and columns.
- Use comments (--) to explain complex queries.
- Test queries with sample data to ensure correctness, especially with edge cases.
- Be mindful of NULL values; use IS NULL or IS NOT NULL for checks.
- Use parameterized queries in applications to prevent SQL injection.

Additional Tips:
----------------
- Use DISTINCT to remove duplicate rows: SELECT DISTINCT column FROM table;
- Use GROUP BY to aggregate data: SELECT column, COUNT(*) FROM table GROUP BY column;
- Use JOINs to combine data from multiple tables.
- Use EXPLAIN to analyze query performance.

These notes cover essential SQL concepts and best practices. Review them regularly to reinforce your understanding and prepare for interviews.




Aggregate Functions:
--------------------
- Aggregate functions process multiple input values and return a single output value.
- They are used only in the SELECT or HAVING clauses.

Common aggregate functions:
- AVG(): Returns the average (mean) value. Returns a float, often with many decimal places. Use ROUND() to limit decimals.
- COUNT(): Returns the number of values (rows).
- MAX(): Returns the maximum value.
- MIN(): Returns the minimum value.
- SUM(): Returns the sum of all values.

Example:
SELECT AVG(salary) FROM employees;
SELECT COUNT(*) FROM orders;
SELECT MAX(price) FROM products;
SELECT MIN(age) FROM users;
SELECT SUM(amount) FROM payments;

GROUP BY:
---------
- GROUP BY is used to group rows that have the same values in specified columns, often used with aggregate functions.
- You can group by one or more columns.
- GROUP BY comes right after FROM clause.
- Every column in the SELECT list that is not an aggregate must be included in the GROUP BY clause.

Example:
SELECT company, division, SUM(sales)
FROM finance_table
GROUP BY company, division;

- If you select a column without aggregation and do not include it in GROUP BY, you will get an error.

Incorrect:
SELECT company, division, SUM(sales) FROM finance_table; -- Error: division must appear in the GROUP BY clause

- You can use multiple columns for grouping.

Filtering Aggregated Results:
-----------------------------
- Use WHERE to filter rows before aggregation.
- Use HAVING to filter groups after aggregation.

Example:
SELECT company, SUM(sales)
FROM finance_table
WHERE division IN ('marketing', 'transport')
GROUP BY company
HAVING SUM(sales) > 10000;

ORDER BY with Aggregates:
-------------------------
- To sort by an aggregate result, reference the entire aggregate function in ORDER BY.

Example:
SELECT company, SUM(sales)
FROM finance_table
GROUP BY company
ORDER BY SUM(sales) DESC
LIMIT 5;

Dates in GROUP BY:
------------------
- To group by date (ignoring time), use a date function to extract the date part from a timestamp.

Example:
SELECT DATE(payment_date) AS pay_date, SUM(amount)
FROM payment
GROUP BY DATE(payment_date)
ORDER BY SUM(amount) DESC;

HAVING:
------
- HAVING is used to filter groups created by GROUP BY based on aggregate conditions.
- WHERE filters rows before grouping; HAVING filters after aggregation.
- Use HAVING with aggregate functions (e.g., SUM(), COUNT(), AVG()) to restrict which groups appear in the result.

Examples:
- Find departments with more than 10 employees:
  SELECT department, COUNT(*) 
  FROM employees 
  GROUP BY department 
  HAVING COUNT(*) > 10;   -> Note Having comes after GROUP BY clause

- Show products with total sales over $1000:
  SELECT product_id, SUM(sales) 
  FROM orders 
  GROUP BY product_id 
  HAVING SUM(sales) > 1000;

- Honoring customers : Customer iDs that has 40 or more transactions would get platinum batch:
  SELECT customer_id, COUNT(payment_id) FROM payment
  GROUP BY customer_id
  HAVING COUNT(payment_id) >= 40

- Customer_ids who spent more than 100$ in payment with our staff_id member 2:
  SELECT customer_id, SUM(amount) FROM payment
  WHERE staff_id = 2
  GROUP BY customer_id
  HAVING SUM(amount) > 100


Notes:
- You cannot use column aliases defined in SELECT in the HAVING clause in some databases; use the full aggregate expression.
- HAVING can be used without GROUP BY to filter on aggregates over the entire result set.

AS Clause (Column Aliasing):
----------------------------

- The AS keyword is used to rename columns or expressions in the result set for clarity.
- Aliases are useful for readability, especially for aggregated columns or calculated fields.

Syntax:
SELECT column_name AS alias_name
FROM table_name;

Examples:
- Rename a column:
  SELECT customer_id AS cus_id
  FROM customer;

  -- The result will show 'cus_id' as the column header.

- Rename an aggregate result:
  SELECT customer_id, SUM(amount) AS total_spent
  FROM payment
  GROUP BY customer_id;

  -- The result will show 'total_spent' as the column header for the sum.

Notes:
- Aliases created with AS are only available in the SELECT and ORDER BY clauses, not in WHERE or GROUP BY.
- The AS keyword is optional; you can also write: SELECT customer_id cus_id FROM customer;
- Use double quotes for aliases with spaces or special characters: SELECT column AS "Alias Name"

LEFT OUTER JOIN:

- LEFT OUTER JOIN returns all rows from the left table, and the matching rows from the right table.
- If there is no match in the right table, NULL values are returned for the right table columns.
- Useful when you want to keep all records from the left table regardless of matches.

Syntax:
SELECT column_name(s)
FROM table1
LEFT OUTER JOIN table2
ON table1.column_name = table2.column_name;

Example:
SELECT customer.customer_id, customer.first_name, payment.payment_id, payment.amount
FROM customer
LEFT OUTER JOIN payment
ON customer.customer_id = payment.customer_id;

-- This returns all customers and their payments. Customers with no payments will show NULL in payment columns.

Scenario:
Find all customers and their total spending, including customers who haven't made any payments.

Solution:
SELECT customer.customer_id, customer.first_name, COUNT(payment.payment_id) AS payment_count, COALESCE(SUM(payment.amount), 0) AS total_spent
FROM customer
LEFT OUTER JOIN payment
ON customer.customer_id = payment.customer_id
GROUP BY customer.customer_id, customer.first_name
ORDER BY total_spent DESC;

-- COALESCE replaces NULL with 0 for customers with no payments.

Notes:
- All rows from the left table are preserved.
- Use WHERE to filter NULL values if you only want unmatched rows: WHERE payment.payment_id IS NULL


RIGHT OUTER JOIN:

- RIGHT OUTER JOIN returns all rows from the right table, and the matching rows from the left table.
- If there is no match in the left table, NULL values are returned for the left table columns.
- Essentially the opposite of LEFT OUTER JOIN.

Syntax:
SELECT column_name(s)
FROM table1
RIGHT OUTER JOIN table2
ON table1.column_name = table2.column_name;

Example:
SELECT customer.customer_id, customer.first_name, payment.payment_id, payment.amount
FROM customer
RIGHT OUTER JOIN payment
ON customer.customer_id = payment.customer_id;

-- This returns all payments and their associated customers. Payments with no matching customer will show NULL in customer columns.

Scenario:
Find all payments and identify which ones have valid customer records.

Solution:
SELECT payment.payment_id, payment.amount, customer.customer_id, customer.first_name
FROM customer


RIGHT OUTER JOIN payment
ON customer.customer_id = payment.customer_id
WHERE customer.customer_id IS NULL;

-- This shows orphaned payments with no matching customer record.

Notes:
- All rows from the right table are preserved.
- RIGHT OUTER JOIN is less commonly used; consider rewriting as LEFT OUTER JOIN by switching table order for clarity.
- Use WHERE to filter NULL values if you only want unmatched rows: WHERE customer.customer_id IS NULL
