SQL Notes

General Guidelines:
-------------------
- SQL syntax is generally applicable to all relational databases (e.g., PostgreSQL, MySQL, etc.).
- Avoid using SELECT * unless you need all columns. Selecting all columns can slow down your application and increase network traffic.
- Capitalize all SQL keywords for readability. End each statement with a semicolon (;).
- Use lowercase for table and column names to distinguish them from SQL keywords.
- Avoid using SQL reserved keywords as table or column names. If unavoidable, use double quotes (e.g., "length") but it's better to choose different names.

COUNT():
--------
- Use COUNT() to return the number of rows matching a query.
- Example: SELECT COUNT(*) FROM table_name;

String Literals:
----------------
- Use single quotes for string values in SQL.
- Example: WHERE rating = 'R'

ORDER BY:
---------
- Use ORDER BY to sort results by one or more columns.
- You can specify ASC (ascending, default) or DESC (descending).
- You do not have to select the column you sort by, but including it improves clarity.
- Example: SELECT title FROM film ORDER BY length DESC;

LIMIT:
------
- LIMIT restricts the number of rows returned.
- Syntax: LIMIT number_of_rows
- LIMIT is placed at the end of the query.
- Example: SELECT * FROM table_name LIMIT 10;

BETWEEN & NOT BETWEEN:
----------------------
- Use BETWEEN to filter results within a range (inclusive).
- For dates, use ISO 8601 format (YYYY-MM-DD).
- Example: WHERE date BETWEEN '2023-01-01' AND '2023-12-31'
- Be cautious with date ranges; check database documentation for inclusivity.

IN & NOT IN:
------------
- Use IN to match any value in a list.
- Example: WHERE color IN ('red', 'blue', 'green')
- Use NOT IN to exclude values.
- Example: WHERE color NOT IN ('red', 'blue', 'green')

LIKE & ILIKE:
-------------
- LIKE is used for pattern matching (case-sensitive).
- ILIKE is used for case-insensitive pattern matching (PostgreSQL only).
- % matches any sequence of characters.
- _ matches a single character.
- Examples:
  - WHERE name LIKE 'A%'      -- names starting with 'A'
  - WHERE name LIKE '%a'      -- names ending with 'a'
  - WHERE last_name LIKE '%eh%'   -- contains 'eh'
  - WHERE last_name LIKE '_eh%'   -- second and third letters are 'eh'
  - WHERE first_name NOT LIKE '%her%' -- does not contain 'her'
- Combine % and _ for flexible patterns.
- Note: LIKE is case-sensitive in most databases; use ILIKE for case-insensitive search in PostgreSQL.

Best Practices:
---------------
- Always use clear and descriptive names for tables and columns.
- Use comments (--) to explain complex queries.
- Test queries with sample data to ensure correctness, especially with edge cases.
- Be mindful of NULL values; use IS NULL or IS NOT NULL for checks.
- Use parameterized queries in applications to prevent SQL injection.

Additional Tips:
----------------
- Use DISTINCT to remove duplicate rows: SELECT DISTINCT column FROM table;
- Use GROUP BY to aggregate data: SELECT column, COUNT(*) FROM table GROUP BY column;
- Use JOINs to combine data from multiple tables.
- Use EXPLAIN to analyze query performance.

These notes cover essential SQL concepts and best practices. Review them regularly to reinforce your understanding and prepare for interviews.




Aggregate Functions:
--------------------
- Aggregate functions process multiple input values and return a single output value.
- They are used only in the SELECT or HAVING clauses.

Common aggregate functions:
- AVG(): Returns the average (mean) value. Returns a float, often with many decimal places. Use ROUND() to limit decimals.
- COUNT(): Returns the number of values (rows).
- MAX(): Returns the maximum value.
- MIN(): Returns the minimum value.
- SUM(): Returns the sum of all values.

Example:
SELECT AVG(salary) FROM employees;
SELECT COUNT(*) FROM orders;
SELECT MAX(price) FROM products;
SELECT MIN(age) FROM users;
SELECT SUM(amount) FROM payments;

GROUP BY:
---------
- GROUP BY is used to group rows that have the same values in specified columns, often used with aggregate functions.
- You can group by one or more columns.
- Every column in the SELECT list that is not an aggregate must be included in the GROUP BY clause.

Example:
SELECT company, division, SUM(sales)
FROM finance_table
GROUP BY company, division;

- If you select a column without aggregation and do not include it in GROUP BY, you will get an error.

Incorrect:
SELECT company, division, SUM(sales) FROM finance_table; -- Error: division must appear in the GROUP BY clause

- You can use multiple columns for grouping.

Filtering Aggregated Results:
-----------------------------
- Use WHERE to filter rows before aggregation.
- Use HAVING to filter groups after aggregation.

Example:
SELECT company, SUM(sales)
FROM finance_table
WHERE division IN ('marketing', 'transport')
GROUP BY company
HAVING SUM(sales) > 10000;

ORDER BY with Aggregates:
-------------------------
- To sort by an aggregate result, reference the entire aggregate function in ORDER BY.

Example:
SELECT company, SUM(sales)
FROM finance_table
GROUP BY company
ORDER BY SUM(sales) DESC
LIMIT 5;

Dates in GROUP BY:
------------------
- To group by date (ignoring time), use a date function to extract the date part from a timestamp.

Example:
SELECT DATE(payment_date) AS pay_date, SUM(amount)
FROM payment
GROUP BY DATE(payment_date)
ORDER BY SUM(amount) DESC;

HAVING
:
------
- HAVING is used to filter groups created by GROUP BY based on aggregate conditions.
- WHERE filters rows before grouping; HAVING filters after aggregation.
- Use HAVING with aggregate functions (e.g., SUM(), COUNT(), AVG()) to restrict which groups appear in the result.

Examples:
- Find departments with more than 10 employees:
  SELECT department, COUNT(*) 
  FROM employees 
  GROUP BY department 
  HAVING COUNT(*) > 10;   -> Note Having comes after GROUP BY clause

- Show products with total sales over $1000:
  SELECT product_id, SUM(sales) 
  FROM orders 
  GROUP BY product_id 
  HAVING SUM(sales) > 1000;

- Honoring customers : Customer iDs that has 40 or more transactions would get platinum batch:
  SELECT customer_id, COUNT(payment_id) FROM payment
  GROUP BY customer_id
  HAVING COUNT(payment_id) >= 40

- Customer_ids who spent more than 100$ in payment with our staff_id member 2:
  SELECT customer_id, SUM(amount) FROM payment
  WHERE staff_id = 2
  GROUP BY customer_id
  HAVING SUM(amount) > 100


Notes:
- You cannot use column aliases defined in SELECT in the HAVING clause in some databases; use the full aggregate expression.
- HAVING can be used without GROUP BY to filter on aggregates over the entire result set.
